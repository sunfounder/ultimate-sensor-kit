12. Bluetooth RGB Controller

One message carries three numbers: how much red, how much green, how much blue. Send R255G128B0 and the LED turns orange.

This is the first structured message in the Bluetooth part - the sketch has to split it into three parts before it can use it, a small job you will meet everywhere.

1. Build the Circuit

Note

The module draws a high current at start-up, so make sure the 9 V battery or an external power supply is plugged into the DC jack of the R4 Minima.

  • Arduino UNO R4 Minima Board

  • ESPC2-01 Module

  • RGB Module

2. Upload the Code

  1. Open the 12-Bluetooth_RGB_controller.ino file under the path of ultimate-sensor-kit\code\iot_project_espc201\bluetooth\12-Bluetooth_RGB_controller.

  2. Select Arduino UNO R4 Minima and the right port, then click Upload.

  3. Open the Serial Monitor at 115200. You should read:

    === ESPC2-01 Bluetooth (BLE) ===
[OK] BLE is ready - scan for "SunFounder-C2" on your phone
--------------------------------

    If you read [!] no reply from the module, the module is not answering on D0/D1 - check the four wires and the power supply.

3. Change the Colour from the Phone

  1. Open LightBlue, tap Scan and connect to SunFounder-C2.

  2. Expand the service 0xA002 and open the characteristic C304. Then tap Write new value.

  3. Set the format in the top right corner to UTF-8 String and type R255G128B0. The picture shows the field just before sending:

  4. Send it. The LED turns orange and the Serial Monitor prints colour: R255G128B0.

    Note

    The sketch does not react to every single character. A BLE write can be split into several pieces on its way, so the sketch waits until the message is complete - a # at the end, or 120 ms of silence - and only then sets the colour. If it acted on each piece, the LED would flash through the wrong colours on every send.

  5. Try a few more - the field stays open, so you can send again right away:

    Send this

    What happens

    R255G0B0

    red

    R0G255B0

    green

    R0G0B255

    blue

    R255G255B255

    white, all three channels at full

    R0G0B0

    off

    Note

    The numbers are 0 to 255, not percentages. R128G0B0 is a darker red than R255G0B0, because the pin is switched on for only half of the time.

    The whole message has to stay under 12 characters, which is why there are no separators.

4. Code explanation

  1. Three pins, one colour

    const int redPin = 9;
const int greenPin = 10;
const int bluePin = 11;

    analogWrite(pin, 0..255) uses PWM, so the LED can show many colours - not just the three primary ones.

  2. Splitting the message

    if (r_char == 'R') { currentColor = 'R'; redTempValue = ""; }
else if (r_char == 'G') { currentColor = 'G'; greenTempValue = ""; }
else if (r_char == 'B') { currentColor = 'B'; blueTempValue = ""; }

if (currentColor == 'R' && r_char != 'R') redTempValue += r_char;

    The letter R, G or B marks where a number starts. Every character after a marker is added to that colour until the next marker arrives. That is why the order R...G...B... matters and why no brackets are needed.

  3. From text to number

    analogWrite(redPin,   redTempValue.toInt());
analogWrite(greenPin, greenTempValue.toInt());
analogWrite(bluePin,  blueTempValue.toInt());

    toInt() converts the text "255" into the number 255. Forgetting it is a classic mistake - analogWrite would then act on garbage.

  4. The 12 character limit

    #define max_char 12

    One BLE write carries at most 20 bytes and this sketch keeps a little headroom. R255G255B255 is 12 characters - the longest useful message.
